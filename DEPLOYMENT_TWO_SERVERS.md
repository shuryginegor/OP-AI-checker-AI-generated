# ПОЛНОЕ ПОШАГОВОЕ РУКОВОДСТВО ПО РАЗДЕЛЬНОМУ ДЕПЛОЮ НА 2 СЕРВЕРА
# (Российский Сервер + Зарубежный Сервер)

Настоящее руководство содержит исчерпывающее, пошаговое описание развертывания проекта на двух независимых серверах в строгом соответствии с требованиями безопасности и 152-ФЗ РФ:

* **ЗАРУБЕЖНЫЙ СЕРВЕР (Foreign VPS):**
  * Содержит **только легкий Telegram-бот**.
  * Обеспечивает бесперебойное, моментальное подключение к серверам Telegram (`api.telegram.org`) без риска блокировок или сетевых задержек.
  * Принимает команды кураторов, генерирует разовые ссылки на веб-отчеты и регистрирует задания в БД.
  * **НЕ скачивает видео**, **НЕ нагружает процессор и канал**, **НЕ обращается к GigaChat**.

* **РОССИЙСКИЙ СЕРВЕР (Russian VPS):**
  * **PostgreSQL 16** — персональные данные преподавателей и кураторов локализованы строго в РФ (152-ФЗ).
  * **Фоновый процессор (`worker_processor.py`)** — скачивает видеозаписи лекций и материалы через КТалк API, извлекает аудиодорожки и репрезентативные кадры через `ffmpeg`, передает на экспертный анализ в **Сбер GigaChat-2-Pro** (через сертификаты Минцифры РФ) и отправляет готовый отчет куратору в Telegram через Bot API.
  * **Веб-платформа (Node.js 20 + React Vite)** — интерактивные графики, статистика преподавателей, разовые сгорающие ссылки и редактор системного промпта нейросети с двухфакторной аутентификацией (2FA) через Telegram.

## ЭТАП 1: ПОДГОТОВКА СЕРВЕРОВ (НА ОБОИХ СЕРВЕРАХ)

На обоих арендованных виртуальных серверах (VPS) под управлением **Ubuntu 22.04 LTS / 24.04 LTS** или **Debian 12** выполните базовую установку Docker:

```bash
# Обновление пакетов ОС
sudo apt-get update && sudo apt-get upgrade -y

# Установка curl, git, ufw
sudo apt-get install -y curl git ufw ca-certificates

# Установка Docker и Docker Compose V2 официальным скриптом
curl -fsSL https://get.docker.com | sh

# Разрешаем запуск docker без sudo (опционально)
sudo usermod -aG docker $USER
newgrp docker

# Проверяем установку:
docker --version
docker compose version
```

## ЭТАП 2: РАЗВЕРТЫВАНИЕ РОССИЙСКОГО СЕРВЕРА (ПЕРВЫЙ ШАГ)

Российский сервер поднимается **первым**, так как именно на нем запускается база данных PostgreSQL, к которой затем подключится зарубежный бот.

### Шаг 2.1. Копирование файлов на Российский сервер
На вашем локальном компьютере или сервере скопируйте содержимое папки `deploy/russian_server` на российский VPS (замените `IP_RUSSIAN_SERVER` на реальный IP):

```bash
# Пример копирования через scp:
scp -r deploy/russian_server/* user@IP_RUSSIAN_SERVER:/home/user/olymp_server/
```

Либо, если вы клонируете весь репозиторий прямо на сервер:
```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ> /home/user/olymp_server
cd /home/user/olymp_server/deploy/russian_server
```

### Шаг 2.2. Настройка переменных окружения (.env)
В папке `/home/user/olymp_server` создайте рабочий файл `.env` из шаблона:
```bash
cp .env.example .env
nano .env
```

Заполните значения:
```env
# 1. Порт веб-приложения (по умолчанию 3000)
PORT=3000

# 2. Токен бота из @BotFather (нужен серверу для отправки 2FA-кодов и готовых отчетов в чат)
BOT_TOKEN=7123456789:AAHabcdef_1234567890abcdef

# 3. База данных PostgreSQL 16
DB_USER=postgres
DB_PASSWORD=УкажитеСложныйИНадежныйПарольБД123!
DB_NAME=lecture_db
DB_PORT=5432

# 4. Токен КТалк API для скачивания лекций на российский сервер
TALK_API_KEY=ваш_токен_кталк_api

# 5. Авторизация в Сбер GigaChat (выполняется строго из РФ через сертификаты Минцифры!)
GIGACHAT_CREDENTIALS=ваш_токен_авторизации_сбера_base64
GIGACHAT_SCOPE=GIGACHAT_API_CORP
GIGACHAT_MODEL=GigaChat-2-Pro

# 6. Секретный криптографический ключ подписи ссылок (HMAC-SHA256)
# ВНИМАНИЕ: Обязательно сохраните его, он должен совпадать со значением на зарубежном сервере!
TOKEN_SECRET=сгенерируйте_случайную_строку_из_32_символов_или_оставьте_дефолт

# 7. Список администраторов (логины в Telegram без символа @, через запятую)
ADMIN_USERNAMES=shurygin_egor,aemss72
PROMPT_ADMIN_USERNAMES=shurygin_egor,aemss72

# 8. Логирование и режим работы
LOG_LEVEL=INFO
TESTING_MODE=false
```

### Шаг 2.3. Настройка сетевого экрана (Брандмауэр UFW)
Чтобы база данных PostgreSQL была доступна **только** для зарубежного сервера бота, а веб-панель была доступна в интернете:

```bash
# Разрешаем SSH для доступа
sudo ufw allow 22/tcp

# Разрешаем веб-порты (для сайта и отчетов)
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 3000/tcp

# Открываем порт PostgreSQL 5432 ТОЛЬКО ДЛЯ IP-АДРЕСА ЗАРУБЕЖНОГО СЕРВЕРА:
# (замените 194.xx.xx.xx на реальный публичный IP зарубежного сервера!)
sudo ufw allow from 194.xx.xx.xx to any port 5432 proto tcp

# Включаем брандмауэр
sudo ufw enable
sudo ufw status verbose
```
*Таким образом, порт базы данных 5432 полностью защищен от сканирования и атак из глобальной сети.*

### Шаг 2.4. Запуск сервисов Российского сервера
В директории с файлом `docker-compose.yml` выполните команду сборки и запуска в фоновом режиме:
```bash
docker compose up -d --build
```

### Шаг 2.5. Проверка состояния сервисов
```bash
# Проверяем, что оба контейнера (olymp_postgres_server и olymp_web_platform) имеют статус "Up"
docker compose ps

# Просматриваем логи веб-платформы и воркера:
docker compose logs -f web
```
В логах вы увидите:
```text
[Telegram Bot] Веб-сервер работает в автономном режиме. Бот хостится на зарубежном сервере.
[Russian Worker] Запуск фонового процессора обработки лекций worker_processor.py...
База данных PostgreSQL успешно инициализирована.
Server running on port 3000
```

### Шаг 3.2. Настройка переменных окружения (.env)
Создайте `.env` файл:

```bash
cp .env.example .env
```

Заполните параметры:
```env

# 2. Подключение к PostgreSQL на РОССИЙСКОМ сервере
```

## ЭТАП 4: СКВОЗНАЯ ПРОВЕРКА РАБОТОСПОСОБНОСТИ

После запуска обоих серверов протестируйте полный рабочий цикл:

1. **Вход в Telegram:**
   * Откройте Telegram и напишите вашему боту: `/start`.
   * Бот ответит мгновенно (так как сервер за рубежом общается с Telegram напрямую без задержек) и покажет меню куратора.

2. **Проверка лекции:**
   * Нажмите кнопку **«📅 Проверить встречу»**.
   * Отправьте ссылку на запись КТалк (например, `https://.../recordings/...`).
   * Выберите имя преподавателя и подтвердите запуск.
   * Бот на зарубежном сервере мгновенно зафиксирует задачу в российской базе данных и выведет:
     > *«📥 Заявка на проверку #1 зарегистрирована! Российский сервер аналитики скачивает лекцию и анализирует через Сбер GigaChat-2-Pro...»*

3. **Работа воркера на российском сервере:**
   * Посмотрите логи на российском сервере (`docker compose logs -f web`).
   * Вы увидите:
     ```text
     [Воркер РФ] Начало обработки лекции #1...
     Загрузка видеофайла (900p) в temp_lectures/...
     [Media] Извлечение аудиодорожки через ffmpeg...
     Загрузка аудиодорожки и кадров в Сбер GigaChat...
     GigaChat задача успешно выполнена и сохранена в БД!
     ```
   * Воркер в РФ сам отправит подробное сообщение с оценкой качества, штрафными баллами и таймкодами нарушений прямо в чат куратора в Telegram.

4. **Интерактивные веб-отчеты со статистикой:**
   * В боте нажмите **«📊 Статистика преподавателя»** и выберите любого преподавателя.
   * Бот выдаст кнопку с подписанной ссылкой на российский сервер:
     `https://metodist.your-domain.ru/?token=st_...`
   * Открыв ссылку в браузере, вы увидите полный веб-дашборд с графиками динамики, фильтрами и историей занятий.

5. **2FA Редактор системного промпта нейросети:**
   * Откройте в браузере `http://IP_РОССИЙСКОГО_СЕРВЕРА:3000` и перейдите во вкладку **«Редактор промпта ИИ»**.
   * Введите свой username Telegram. Веб-сервер в РФ сгенерирует разовый 6-значный код и отправит его в ваш Telegram-чат через Bot API.
   * Введите код, отредактируйте промпт, нажмите «Сохранить» — код снова подтверждается через Telegram, и новый промпт вступает в силу без перезапуска системы.

## ЧАСТО ЗАДАВАЕМЫЕ ВОПРОСЫ И РЕШЕНИЕ ПРОБЛЕМ

### 1. Бот на зарубежном сервере пишет: `asyncpg.exceptions.CannotConnectNowError` или таймаут подключения к PostgreSQL
* **Причина:** Брандмауэр UFW на российском сервере блокирует порт 5432 или указан неверный внешний IP.
* **Решение:** На российском сервере проверьте команду:
  ```bash
  sudo ufw status
  ```
  Убедитесь, что разрешен доступ:
  ```bash
  sudo ufw allow from <IP_ЗАРУБЕЖНОГО_СЕРВЕРА> to any port 5432 proto tcp
  ```
  Также проверьте, что в файле `docker-compose.yml` на российском сервере у сервиса `postgres` открыт порт `"5432:5432"`.

### 2. Как настроить доменное имя и HTTPS (SSL) на Российском сервере?
Перед веб-сервером на российском сервере рекомендуется поставить классический обратный прокси Nginx с бесплатным сертификатом Let's Encrypt:
```bash
sudo apt install -y nginx certbot python3-certbot-nginx
```
Конфигурация `/etc/nginx/sites-available/metodist`:
```nginx
server {
    server_name metodist.your-domain.ru;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
Активация и получение SSL-сертификата:
```bash
sudo ln -s /etc/nginx/sites-available/metodist /etc/nginx/sites-enabled/
sudo certbot --nginx -d metodist.your-domain.ru
```

### 3. Как обновить код проекта в будущем?
* **На Российском сервере:**
  ```bash
  cd /home/user/olymp_server/deploy/russian_server
  git pull
  docker compose up -d --build
  ```
* **На Зарубежном сервере:**
  ```bash
  cd /home/user/olymp_bot/deploy/foreign_server
  git pull
  docker compose up -d --build
  ```
База данных при перезапусках контейнеров **не стирается**, так как сохраняется в постоянном томе Docker `postgres_data`.
