# Архитектура и соответствие 152-ФЗ «О персональных данных»

В данном документе описана архитектура сервиса **«Анализатор лекций Олимпиадные Практики»** с учетом требований законодательства Российской Федерации в области персональных данных (ПДн).

---

## 1. Локализация персональных данных (ч. 5 ст. 18 152-ФЗ)

### Требование закона
При сборе персональных данных (ФИО преподавателей, Telegram ID, списки разрешенных пользователей, результаты проверок лекций) оператор обязан обеспечить их первичную запись, систематизацию, накопление, хранение, уточнение и извлечение в **базах данных, находящихся на территории РФ**.

### Реализация в проекте
1. **Первичная база данных (Primary Database)**:
   - В боевом режиме (`DB_TYPE=postgres`) БД PostgreSQL размещается в российском дата-центре (например, Yandex Cloud, Selectel, VK Cloud или собственный сервер в РФ).
   - Все операции чтения/записи (таблицы `allowed_users`, `authorized_users`, `teachers`, `responses`, `stats_tokens`) выполняются напрямую в этой РФ-БД.
   - В режиме разработки и тестирования (`DB_TYPE=sqlite`) используется локальная SQLite БД (`bot_database.db`), также находящаяся на локальном сервере разработчика.

---

## 2. Полное импортозамещение и отечественная обработка данных (GigaChat API)

### Архитектурное преимущество GigaChat:
- Проект полностью переведён на работу с **GigaChat API (Сбер)**, функционирующим исключительно на серверах внутри Российской Федерации.
- Все обращения к API шифруются по TLS с использованием отечественных доверенных сертификатов безопасности Минцифры РФ (Госуслуги / НУЦ).
- Таким образом, трансграничная передача персональных данных в части ИИ-аналитики **полностью исключена**.

### Защитные меры и регламент:
1. **Минимизация и обезличивание данных (Деперсонализация)**:
   - В нейросеть отправляются только методические материалы лекции и технический аудиотрек.
   - Из промптов исключаются чувствительные персональные данные (номера телефонов, адреса, паспортные данные).
2. **Временная транзитная обработка и удаление файлов**:
   - Аудиофайлы и скриншоты с КТалк скачиваются исключительно во временную папку сервера, загружаются во временное хранилище GigaChat Files API и **немедленно удаляются как с локального диска, так и из облака GigaChat** сразу после генерации рецензии.
   - Функция очистки `_cleanup_gigachat_files` гарантирует удаление всех артефактов из GigaChat.

## 4. Запуск в режиме разработки и тестирования

В соответствии с указаниями, для текущего тестирования PostgreSQL не используется:
- `DB_TYPE=sqlite` по умолчанию в `.env`.
- При вызове `database.init_db()` система проверяет доступность PostgreSQL. Если PostgreSQL недоступен, автоматически происходит fallback на локальную SQLite БД (`bot_database.db`), что обеспечивает безопасную локальную отладку без подключения к внешним СУБД.
